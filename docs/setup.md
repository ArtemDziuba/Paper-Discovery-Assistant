# Local setup and demonstration

Requirements: Python 3.12 or later and uv. Run from the repository root:

For the final human/synthetic ranking comparison and the commands to reproduce it, see
ranking-evaluation.md. Run `uv run --extra cuda python scripts/evaluate_annotations.py`
to evaluate available methods on the fixed two human and ten synthetic batches. V2 is included
automatically when models/syntetic-finetune-v2/training_manifest.json is present. The frozen
snapshot is evaluation/annotations/prepared.json and results go to evaluation/results/.
Use a new --output path when repeating a run; existing reports are not overwritten.
The default --mode truncated reports primary nDCG@10/Precision@5 plus MAP@10/pairwise
accuracy. Use --mode full for all requested cutoffs; see full-ranking-evaluation.md for
commands and the executed results saved in evaluation/results/ranking-comparison-full.json.

```powershell
uv sync
uv run streamlit run app.py
```

Open the localhost URL printed by Streamlit. The first semantic search sets up the pinned
encoder under models/all-MiniLM-L6-v2. It reuses already cached Hugging Face weights when
available, otherwise downloading the model. Later launches load weights, tokenizer and
configuration directly from that project folder with local_files_only=True. No model-server
connection is needed after setup. Uncached arXiv searches still need internet. Select TF-IDF
baseline to run without model setup.

Per-paper full-text summarization is optional and uses a separate local Ollama service.
Install Ollama manually, run `ollama pull qwen3.5:4b` once, then click **Summarize** on a
result. No summary is generated by searching. See [summarization.md](summarization.md) for
installation, all environment settings, the PDF/summary cache, processing limits and quality
validation. The app never downloads the language model during a summary request. After
updating dependencies, `uv run --extra cuda python -m streamlit run app.py` launches through
Python directly and avoids a stale Streamlit launcher script.

PDF parsing now requires PyMuPDF >=2.1,<3, with version 2.1 recorded in `uv.lock`.
Its layout analysis runs locally on CPU; OCR is explicitly disabled. Existing environments
can upgrade with `.venv\Scripts\python.exe -m pip install --upgrade "pymupdf>=2.1,<3"`;
run `.venv\Scripts\python.exe -m ensurepip --upgrade` first if pip is absent. Restart
Streamlit after upgrading. `uv sync --extra cuda` also installs the locked PDF dependencies.

The folder is independent of models/finetuned-minilm and is excluded from Git by the existing
models/ rule. The pda_source.json file records the pinned base model and revision; keep it
alongside the complete saved model. Setup publishes the folder only after saving succeeds,
so an interrupted setup can be retried. An existing folder with missing/incorrect source
metadata or unreadable weights produces an error without automatic re-downloading. Restore
the complete folder, or rename it and retry to create a fresh installation.

On Windows, the model folder must be readable by the account running Streamlit. An earlier
setup used owner-only temporary-directory permissions; publishing that folder from the coding
sandbox blocked the normal user's access, which appeared as a revision error. The existing
installation's inherited permissions were restored on 2026-11-08, and setup now preserves
project permission inheritance. Access-denied source reads now have a distinct diagnostic.
Offline CUDA loading was verified under the normal Windows account in
evaluation/model-storage-user-account.json; model weights were not changed.

To set up the base model before opening the app and verify offline loading:

```powershell
uv run --extra cuda python scripts/verify_model_storage.py --device cuda
```

This command also checks that the saved model produces the same sample embeddings as the
pinned encoder in the Hugging Face cache, so retaining that cache is needed for its reference
comparison. Normal app loading uses only the project folder after setup. The command saves
evaluation/model-storage.json; use a new --output path for another verification. It blocks
socket connections during the second load and sample inference. The executed 2026-11-08 run
passed on CUDA with zero observed embedding difference for three texts. Its timings are
within one already imported process and do not establish faster complete application startup.

If retrieval fails, inspect the specific connection, timeout, or HTTP error shown in the
interface and the terminal log. Run the command above in your own terminal; a server
started inside a coding assistant's sandbox may render normally while outbound arXiv
connections are blocked (Windows socket error 10013). Cached searches can still succeed
in that situation, so they do not prove that live retrieval is available.

Source file watching is disabled in .streamlit/config.toml to avoid Streamlit inspecting
lazy Transformers imports for unrelated optional image/audio dependencies. Restart the
server after editing source files.

CPU is the default to avoid assuming a CUDA-enabled PyTorch installation. Select CUDA
only after checking `uv run python -c "import torch; print(torch.cuda.is_available())"`.
A CUDA-compatible PyTorch build must match your driver; follow the official PyTorch
installation selector at https://pytorch.org/get-started/locally/ if replacement is needed.
No claim of measured hardware compliance is made until a representative run is profiled.

For this Windows RTX 4060 laptop, the optional CUDA environment is pinned to PyTorch 2.9.1
from the official CUDA 12.8 wheel index. The driver must support that runtime. Install and
launch with the extra enabled (the initial GPU download is approximately 2.7 GiB):

```powershell
uv sync --extra cuda
uv run --extra cuda python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
uv run --extra cuda streamlit run app.py
```

Keep `--extra cuda` on `uv run` commands when using the GPU environment; otherwise uv may
restore the default CPU dependency selection. The CUDA build also supports CPU inference.
Selecting cuda in the interface cannot add CUDA support to a CPU-only PyTorch build.
The app checks availability before model loading and reports an actionable error.

The Ranking selector also offers `syntetic finetune v1`, using the saved local model under
models/finetuned-minilm. It is an experimental alternative; the original Semantic option
performed better on the two human evaluation queries and remains the default. See
finetuning.md for its original training experiment and ranking-evaluation.md for the current
comparison. If the v1 weights are absent, restore the saved artifact for that training run.
The v1 prepare_finetuning.py script now reads exactly encoder batches 01–15 from
finetune_data/encoder and human judgments from evaluation/human_eval. It retains v1's original
split/overlap policy, not v2's occurrence-preserving policy. Use a new --output path;
historical snapshots are not overwritten. V2 has dedicated prepare_finetuning_v2.py and train_ranker_v2.py scripts
using all 45 finetune_data/encoder batches; see finetuning-v2.md for parameters and plots.
The selector includes syntetic finetune v2, loading models/syntetic-finetune-v2. Its combined
human/synthetic development set selected the checkpoint, while standalone reports remain
separated. The executed four-model full comparison is evaluation/results/ranking-comparison-full-v2.json.
Restart Streamlit after creating or replacing model artifacts.

The interface requires Streamlit >=1.66 for tracked paper-expander state. Idle/completed
summary panels do not poll; active panels refresh once per second and preserve open/closed
state when timers are registered or removed. Run `uv sync --extra cuda` to apply the lock file.

Topic interpretation removes common leading request phrases and joins remaining concepts
with AND. This reduces broad filler matches but can lose relevant papers with missing terms.
For a known title, enter the complete name, for example `attention is all you need`.
Straight or smart quotation marks are optional. An auxiliary title-field lookup preserves
all words and merges only complete normalized title matches into the candidate set, so
topic stopword removal does not prevent title matching. Exact titles are shown first,
with unchanged cosine scores. No paper IDs are inserted into results.
The lookup can request up to 50 additional entries; the combined usable candidate set
remains within the requested limit. It uses the existing cache and rate limiter.
Run `uv run --extra cuda python scripts/verify_cuda.py` to reproduce CPU/GPU agreement and
the quoted-title regression. Its source candidates must be cached, or internet access is needed.
The newer unquoted/quoted/smart-quoted regression is
`uv run --extra cuda python scripts/verify_title_lookup.py`; results are saved in
evaluation/title-lookup-regression.json.

Displayed papers can be set to 5, 10, 15, …, 50, with 10 selected by default. Choose the count
and submit the search to apply it. Fewer results appear if there are fewer usable candidates.
The cross-paper abstract overview remains removed. Ranked papers retain their individual
abstracts, matching terms, scores and source links; **Summarize** requests a query-focused
full-paper summary on demand. The selected-abstract-evidence section is no longer displayed.
JSON export contains ranked matches and provenance; summaries use their separate local cache.

The candidate control defaults to 1,000 and accepts up to 10,000. This is an upper bound on
raw arXiv entries, not a promise of that many distinct valid papers. Retrieval pages contain
at most 1,000 entries, with rate limiting and retries. Larger uncached searches can take
minutes depending on the API; cached searches still rerank the candidates locally. Watch
the retrieval/encoding progress and the actual usable candidate count. Partial retrieval
after a later page failure is labeled explicitly. Retry to reuse successful cached pages.
The interface displays retrieval time, ranking time, and whether all retrieved pages were
cached. The JSON export also includes total time with model loading and per-page provenance.

```powershell
uv run --extra cuda python scripts/benchmark_candidates.py
```

This retrieves up to 10,000 candidates for the reported transformer topic and compares
50/100/1,000/10,000 prefixes of one snapshot. It records timings, memory and the known paper's
presence in evaluation/candidate-scaling.json. This diagnostic does not supply general
relevance judgments or establish that a higher cosine score means a better paper.

```powershell
uv run pytest
uv run ruff check src tests scripts app.py
uv run python scripts/evaluate.py --help
uv run python scripts/prepare_scifact.py
uv run python scripts/evaluate.py --data evaluation/data/scifact-test.json --output evaluation/scifact-lexical.json --method lexical
uv run python scripts/evaluate.py --data evaluation/data/scifact-test.json --output evaluation/scifact-semantic.json --method semantic
```

Dataset preparation downloads BEIR SciFact data; review its original terms before redistribution.
Downloaded data is ignored by Git; evaluation reports are retained. Run
`uv run python scripts/smoke.py` for live retrieval and local-model verification, and
`uv run python scripts/audit_cached.py` for structural checks on retrieved records.

Retrieval pages are cached under .cache/arxiv for 24 hours, keyed by query, offset, page size,
and sort settings. The paginated cache uses a new namespace; older single-request caches
are left untouched but not reused. Delete individual cache
files to force a new search. Invalid cache records are ignored. No automatic stale-cache
fallback or offline replay interface is implemented yet. JSON export includes source IDs,
scores, excerpts, configuration, retrieval timestamps, and stage timings.

that triggers the baseline limitation warning, and an invalid empty query. Explain that
match evidence is extracted from abstracts and scores are not calibrated probabilities.
